# Протокол деплоя

**Где скрипты.** Движок обычно лежит в `/opt/unpacker` — ниже я так и пишу. Если владелец
ставил в другое место, беру фактический путь (`agentctl.sh` и `deploy.sh` лежат в его подпапке
`deploy/`). Зову ВСЕГДА полным путём: короткое имя даст «команда не найдена», а sudo сверяет
ровно тот путь, что перечислен в его whitelist.

Иду ровно по шагам. Не перескакиваю, не объединяю шаг 4 с шагом 6, не деплою «пока владелец
думает». Каждый шаг заканчивается либо сообщением владельцу, либо запуском скрипта.

## Шаг 1. Понять, что разворачиваем

Нужны две вещи: **какая папка-мозг** и **на какую поверхность**. Поверхность сейчас одна —
Telegram (`--surface tg`). Веб — это Фаза 3, standalone — Фаза 2; если просят их, говорю прямо:
«пока не умею, умею Telegram».

Мозг может быть локальной папкой (`/home/user/brains/sales`) или git-адресом. Git не обязателен —
локальной папки достаточно.

## Шаг 2. Собрать данные — ОДНИМ блоком

Один блок вопросов, а не допрос по одному. Дефолты называю сразу, чтобы можно было ответить
«всё по умолчанию»:

```
Чтобы развернуть, нужно 5 вещей:
1. Имя инстанса — латиницей, строчными, через дефис (например sales-bot).
   Это имя каталога и юнита, потом его не переименовать.
2. Токен бота от @BotFather — но НЕ присылай его сюда, положи в файл на сервере
   (три команды дам ниже). В чате секрет остаётся навсегда.
3. Твой Telegram user id (кому можно писать боту). Узнать: напиши @userinfobot.
   Первый в списке = владелец, ему будут приходить алерты о проблемах.
4. Путь к папке-мозгу (или git-адрес).
5. Токен подписки Claude — вывод команды `claude setup-token`, если он ещё не заводился
   на этом сервере. Тоже файлом. Без него бот проживёт до первого протухания и упадёт в 401.
Остальное беру по умолчанию: контур — личная подписка, косметика включена, проактивности нет.
```

### Секреты — через файл, не через чат

Токен в чате остаётся навсегда: он ложится в историю Telegram и в мою же историю сессий на
сервере. Значение из командной строки — навсегда в `/var/log/auth.log`. Поэтому веду так
(владелец делает это на сервере по ssh, я эти команды не запускаю — их нет в моём whitelist):

```
mkdir -p ~/secrets && chmod 700 ~/secrets
nano ~/secrets/<имя>.token       # вставь токен ОДНОЙ строкой, Ctrl+O, Enter, Ctrl+X
chmod 600 ~/secrets/<имя>.token
```

Дальше мне нужен только путь: я передаю его скрипту флагом `--token-file` (для токена
подписки — `--cc-token-file`), скрипт читает файл один раз. После деплоя напоминаю удалить
файл: `shred -u ~/secrets/<имя>.token`.

Если владелец всё-таки прислал токен прямо в чат — не ругаюсь, а: (1) в своих сообщениях
показываю его как `[REDACTED]`, (2) сам сохраняю его в файл `chmod 600` и дальше работаю
через `--token-file`, (3) прямо говорю, что этот токен стоит **перевыпустить** у @BotFather
(токен подписки — заново `claude setup-token`), потому что в переписке он остался навсегда.

Если чего-то из пятёрки не хватает — спрашиваю недостающее, а не начинаю деплой «попробуем».

## Шаг 3. Гейты — их выполняет КОД, я показываю результат

Проверки живут внутри `deploy.sh` (§7.3): токен валиден по getMe, токен не занят другим
инстансом, имя свободно, мозг существует и в нём есть `CLAUDE.md`, рабочее дерево git-мозга
чистое, контур auth выбран. Я их не «прохожу» — я запускаю скрипт и пересказываю его вывод.

Первый запуск — вхолостую, он же и покажет гейты:

```
sudo /opt/unpacker/deploy/deploy.sh --surface tg --name <имя> --token-file ~/secrets/<имя>.token --users <id> --brain <путь> --dry-run
```

Вывод гейтов пересказываю владельцу человеческим языком (5–7 строк, без простыни).

### Если гейт отказал

Гейт — это код: уговорить его нельзя, и обходить я его не пытаюсь — лечу причину.
`--skip-preflight` существует не для обхода гейтов (он их и не снимает), и предлагать его
как «способ проскочить» я не буду.

| Отказ | Что это значит для владельца | Что делаем |
|---|---|---|
| Telegram отверг токен (getMe) | токен неверный или отозван | берём новый у @BotFather |
| Сеть до Telegram недоступна | сервер не видит api.telegram.org | чиним сеть/прокси, потом повторяем — деплой на непроверенном токене я не делаю |
| Токен занят инстансом X | два бота на одном токене дают ошибку 409 и оба начинают терять сообщения | или отдельный бот у @BotFather, или сносим X осознанно |
| Имя занято другим ботом | под этим именем уже живёт другой токен | берём другое имя (переименование = новый инстанс) |
| В мозге нет CLAUDE.md | это не папка-мозг, а просто папка | показываем, где должен лежать файл, и что в нём минимум личность |
| Git-мозг грязный | есть незакоммиченные правки, следующий `git pull` встанет | владелец коммитит или откатывает — сам, я в его правки не лезу |
| Клиентская поверхность на подписке | обслуживать внешних людей с личной подписки запрещено ToS Anthropic и это энфорсится | объясняю и предлагаю внутренний контур; клиентский — Фаза 4 |

## Шаг 4. План и подтверждение

Показываю план: что появится, где, какой командой. Секреты — замазаны.

```
План:
· инстанс: ~/agents/<имя>/ (.env с правами 600, state/ для сессий и файлов)
· мозг:    ~/brains/<имя>/ (копия твоей папки, без .git и .env)
· автозапуск: agent-tg@<имя> — бот сам поднимется после перезагрузки
· команда: sudo /opt/unpacker/deploy/deploy.sh --surface tg --name <имя> --token-file ~/secrets/<имя>.token --users <id> --brain <путь>
Живые боты не задеваю. Займёт около минуты.

Разворачиваю? (да / поправить / стоп)
```

Жду ответ. Без «да» — не двигаюсь. «Поправить» — возвращаюсь к шагу 2 за уточнением.
«Стоп» — останавливаюсь и ничего не запускаю.

## Шаг 5. Деплой

Тот же вызов без `--dry-run`. Если разворачиваю самого себя (мета-агента), добавляю
`--role unpacker` — тогда скрипт поставит ещё drop-in юнита и права на скрипты.

Пока идёт — одна строка «разворачиваю, это меньше минуты». Если скрипт упал, показываю
последние строки его вывода и что они значат. Не запускаю повторно «на удачу»: сначала причина.

## Шаг 6. Проверка

```
sudo /opt/unpacker/deploy/agentctl.sh doctor <имя>
```

Читаю вердикт и пересказываю. `HEALTHY` — говорю, что бот жив и можно писать `/start`.
Есть замечания — перечисляю их человеческим языком и предлагаю первый шаг. Отдельно поясняю
`auth: не проверялся` — это нормально до первого сообщения боту, а не поломка.

Проверка «живым запросом» жжёт квоту подписки, поэтому её делаю только по просьбе.

## Шаг 7. Отчёт

Пишу файл `~/agents/unpacker/state/deploys/<дата>-<name>.md` (дата в формате `2026-07-25`);
каталог создаю, если его нет: `mkdir -p ~/agents/unpacker/state/deploys`.

Путь именно такой, и это не придирка. Моя рабочая папка — папка-мозг, поэтому относительный
`deploys/` писал бы отчёты ВНУТРЬ мозга. Мозг Распаковщика живёт в дереве движка и принадлежит
root — там мне просто не дадут писать; а у обычного агента запись в мозг делает git-дерево
грязным, и следующий деплой встанет на гейте чистоты (§4). Мутабельное живёт в состоянии
инстанса — отчёты тоже.

Формат — ровно такой, чтобы через месяц можно было понять, что происходило:

```markdown
# 2026-07-25 — sales-bot

## Что развернули
Мозг: ~/brains/sales-bot (локальная папка, скопирована)
Инстанс: ~/agents/sales-bot, юнит agent-tg@sales-bot
Контур: подписка (внутренний). Доступ: user id 111111111.

## Гейты
Все пройдены: токен валиден (бот @sales_help_bot), токен свободен, имя свободно,
CLAUDE.md на месте, мозг не git (проверка чистоты не требовалась).

## Проверка
/opt/unpacker/deploy/agentctl.sh doctor sales-bot → HEALTHY. Ответ на /start получен.

## Что дальше
Токен светился в чате — перевыпустить у @BotFather и прогнать деплой ещё раз с новым.
Кнопки-триггеры не заводились: buttons.yaml пуст.
```

Секретов в отчёте нет — ни токена, ни ключа. Имя бота (@…) писать можно.

## Чего я не делаю на этом протоколе

- Не деплою без «да» и без предварительного dry-run.
- Не правлю `.env` руками — только через флаги скрипта (например ротация токена подписки
  через `--cc-token-file`, а не через редактирование файла).
- Не разворачиваю ботов для внешних людей (`--audience client`) — это Фаза 4.
- Не сношу и не рестартую чужие инстансы «на всякий случай».
