# `/etc/unpacker/engine.conf` — машинная карта путей движка

Кто пишет: `install.sh` (шаг после диалога, до деплоя Распаковщика).
Кто читает: `update.sh` и `deploy/_common.sh` (а значит `deploy.sh` и `agentctl.sh`).
Права: `root:root`, `0644` — читать должны все точки входа, писать только root.

## Зачем он есть

Личность движка раньше выводилась из окружения вызывающего:
`TG_RUN_USER` → `SUDO_USER` → `id -un`. Получалось три разных вселенных путей:

| Как позвали | Кем считался движок | Что происходило |
|---|---|---|
| `bash install.sh` от root | `unpacker` (передан явно) | всё правильно |
| `sudo update.sh` от root | **root** | `AGENTS_BASE=/root/agents` → ни бэкапов, ни рестартов, и финальное «готово» |
| `sudo deploy.sh` от агента | `unpacker` (через `SUDO_USER`) | правильно, но `TG_BRAINS_BASE` терялся на `env_reset` |

То есть каждая точка входа читала своё — и **тихо рапортовала успех**
(находки C6, ADV-05/06/09 ревью 1b). Карта путей делает ответ одинаковым для всех.

## Формат

Строки `key=value`, без подстановок, без кавычек, без пробелов вокруг `=`.
Комментарии — строки, начинающиеся с `#`.

```
TG_RUN_USER=unpacker
TG_RUNTIME=/opt/unpacker
TG_AGENTS_BASE=/home/unpacker/agents
TG_BRAINS_BASE=/home/unpacker/brains
TG_UV_BIN=/usr/local/bin/uv
```

Других ключей нет: файл — карта путей, а не общий конфиг.

## Правила чтения (обязательные)

1. **Парсить построчно, НЕ `source`.** Файл читают процессы, работающие от root.
   `source` конфига — тот самый класс дыр, что SEC-1: значение из файла становится кодом.
   Ключи из списка выше принимать, остальные строки молча пропускать.
2. **Приоритет: окружение → `engine.conf` → прежний фолбэк.** Переменная, уже заданная в
   окружении, побеждает: так остаются работать ручные прогоны и тесты.
3. **`TG_RUNTIME` из файла не задаёт каталог движка для `update.sh`.** `update.sh` берёт
   каталог из своего расположения (SEC-1: флага `--engine-dir` больше нет); расхождение с
   конфигом он показывает предупреждением.
4. **Отсутствие файла — не ошибка сама по себе, но ошибка, если из него нужен run-user.**
   `update.sh` при `RUN_USER=root` останавливается и отправляет переустановить движок
   или передать `TG_RUN_USER=` руками: обновляться, не зная, чьи боты обновляешь, нельзя.

## Смежные контракты, которые держит install.sh

- **venv движка вне дерева кода:** `UV_PROJECT_ENVIRONMENT=/var/lib/unpacker/venv`,
  владелец — run-user. Дерево `/opt/unpacker` при этом `root:root` и `go-w`, потому что
  на скрипты внутри выдан NOPASSWD-sudo (см. `rights-model.md`). В `engine.conf` этот путь
  не пишется: он одинаков у всех и зашит в install.sh/update.sh как константа.
  Юнит и `deploy.sh` обязаны использовать то же значение.
- **`TG_UV_BIN` всегда системный путь** (`/usr/local/bin/uv`). uv из домашнего каталога
  root'а (`/root/.local/bin`, mode 700) юниту недостижим — это ADV-01/C4.
- **Секреты в `engine.conf` не попадают никогда.** Ответы ученика без секретов лежат рядом,
  в `/etc/unpacker/install.conf` (0600); токены живут только в `.env` инстанса (0600).
